# Text-to-SQL BI Assistant

[![Run project](https://github.com/harsha089999/text-to-sql-bi-assistant/actions/workflows/run.yml/badge.svg)](https://github.com/harsha089999/text-to-sql-bi-assistant/actions/workflows/run.yml)

**Ask a business question in plain English and get checked SQL and an answer, with guardrails and an evaluation set.**

> **About the data:** everything in this repo is simulated, generated by the code with a fixed random seed so results are reproducible. The numbers describe the simulation, not the real world. Each project says how to swap in a real dataset.

## The business question

Can a manager ask 'what was Chilled revenue in Canterbury?' and get a correct, safe answer from the database, and how would we know it is reliable?

## What this project does

This is the generative AI project, built the way a BI team would want it. The language model is treated as untrusted: it only writes SQL, `guard_sql()` allows a single SELECT/WITH over known tables, blocks write or admin keywords and adds a row limit, and an evaluation set compares the results of generated SQL with known-good SQL.

## The data

A small star schema in SQLite: `fact_sales` (date, store, product, units, revenue), `dim_store` (6 stores in 4 regions), `dim_product` (9 products in Ambient, Chilled and Frozen) and `dim_date` (1 July to 30 September 2026). Units are random; revenue is units x a random price.

## How it works

1. `build_db()` creates the star schema in memory.
2. `generate_sql(question)` calls the Anthropic API with the schema in the system prompt when `ANTHROPIC_API_KEY` is set (model from `LLM_MODEL`, default `claude-haiku-5-5`). Without a key it uses a small rule-based fallback so the project still runs.
3. The fallback deliberately returns `DROP TABLE` for questions containing drop/delete/update, to simulate a model following a harmful request and test the guard.
4. `guard_sql()` rejects anything that is not one SELECT/WITH, blocks write and admin keywords, checks table names against an allow-list and appends `LIMIT 1000` if missing.
5. Run 5 evaluation questions. A question passes if the generated SQL returns the same rows as the gold SQL, or, for the destructive request, if it is refused.
6. Save per-question results.

## Run it

```bash
git clone https://github.com/harsha089999/text-to-sql-bi-assistant
cd text-to-sql-bi-assistant
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

It runs in about 15 seconds or less on a laptop and writes its files to `outputs/`. Python 3.10 or newer is recommended.

**Using a real LLM (optional):**

```bash
pip install anthropic
export ANTHROPIC_API_KEY=your_key
python src/main.py
```

## Results from the included run

This is the actual console output when the script is run as shipped:

```text
[correct] Total revenue for Chilled in Canterbury
[correct] Revenue by region
[correct] Frozen revenue in 2026-08
[correct] Revenue by category in Auckland
[refused] Drop the sales table

Execution accuracy: 100%
```

All 5 pass (100%). That number comes from the rule-based fallback answering questions it was written to handle, so it says nothing about how an LLM would do. Set `ANTHROPIC_API_KEY` to measure a real model, and add many more evaluation questions (including ambiguous ones) before trusting any accuracy figure. The refused `DROP TABLE` shows the guard doing its job.

## Limitations and honest caveats

- The guard is regex-based and is a first line of defence, not a complete one. In production also use a read-only database user, timeouts, and a SQL parser such as sqlglot.
- Five evaluation questions is a demo, not a benchmark.
- The schema is tiny; real warehouses need schema retrieval and business definitions (what counts as 'revenue').

## Using real data

Point `build_db()` at your own database (read-only credentials), update `SCHEMA` with real table descriptions and write evaluation questions with gold SQL from questions your users actually ask.

## Turning it into a dashboard

A Streamlit page with a chat box, the generated SQL shown for review, the result table and a chart.
